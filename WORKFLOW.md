# 🚀 Development Workflow

## 🧭 Roadmap

Defines **where the product is going**.

* `Milestone` = release/goal: `MVP → Beta → v1.0`
* `Area` = permanent capability: `Payments`, `Reservations`
* `Epic` = concrete goal with a clear start and end
* Review at the end of each Sprint.

---

## 📦 Backlog

Everything I **might work on**, but haven't committed to yet.

When a new idea, feature, bug, or improvement comes up:

**Create Issue → `Backlog` → keep working.**

It doesn't need to be fully defined yet.

---

## 🧩 Refinement

Prepare only the Issues I'm likely to work on soon.

Before moving from `Backlog → Ready`:

* Clear goal
* Acceptance Criteria
* Epic, if applicable
* Milestone, if applicable
* Priority
* Points: `1 / 2 / 3 / 5 / 8`
* Can be completed within one Sprint

**Ready = I can start working on it right now.**

---

## 🗓️ Sprint Planning

At the beginning of the week:

1. Define a **Sprint Goal**.
2. Open `📋 Sprint Planning`.
3. Choose `Ready` Issues that contribute to the Goal.
4. Consider Priority and capacity.
5. Assign `Iteration → Current Sprint`.

**Don't fill the Sprint just for the sake of filling it.**

---

## 💻 Current Sprint

Work only from `🏃 Current Sprint`.

**One Issue at a time:**

`Ready → In Progress → In Review → Done`

Before `Done`:

* Acceptance Criteria met
* Working and tested
* Code integrated

Finish → pick the next one.

---

## 💡 Something New Comes Up

Is it necessary to finish the current work?

**Yes →** handle it.

**No →** `Issue → Backlog → continue`.

Don't disrupt the Sprint for every new idea.

---

## 🏁 End of Sprint

### Review

* Did I achieve the Sprint Goal?
* What was completed as `Done`?
* Count completed Points.

### Unfinished Work

It doesn't automatically move to the next Sprint.

If it's still a priority → `Ready`, without an Iteration.
If it's no longer upcoming → `Backlog`.

### Retro

Answer only:

* What worked?
* What slowed me down?
* What will I change next week?

---

# 🔄 Workflow

**Roadmap / Epics**
↓
**Backlog**
↓
**Ready**
↓
**Sprint Planning**
↓
**Current Sprint**
↓
**Done**
↓
**Sprint Review**
↓
**Review Roadmap + Backlog**
↓
**Next Sprint**

---

# ⭐ Rules

1. **One thing at a time.**
2. **New idea → Backlog.**
3. **Ready = ready to develop.**
4. **Iteration = when I work on it.**
5. **Milestone = which release it's for.**
6. **Area = permanent capability.**
7. **Epic = finite goal.**
8. **Done = actually done.**
9. **Don't change the Sprint without a good reason.**
10. **Keep the system simple.**
